# 运行监控页功能与视觉优化设计

## 背景

`node-base-module/base-admin-web/src/views/system/monitor/index.vue` 已接入运行概览、指标趋势、日志检索和告警中心四个工作区。当前页面可以调用后端接口，但查询状态、筛选操作、错误恢复、移动端布局和结果可读性仍偏基础。用户提供的截图确定了当前视觉基线：深色渐变监控头、浅色卡片、紧凑工作区标签和分区面板。

## 目标

在不改变现有后端 API 路径、权限码和路由契约的前提下，完善监控页的可操作性和状态反馈，并让页面在桌面和窄屏下保持一致的层级与可读性。

## 范围

- 保留 `MonitorOverview`、`MetricRange`、`LogPage`、告警规则/活动告警/静默记录等现有类型和接口。
- 优化四个工作区的加载、空数据、错误和刷新反馈。
- 日志筛选增加可重置的查询状态、时间范围字段（仅在已有 API `startTime` / `endTime` 上透传）、加载更多和详情查看体验。
- 指标趋势补充查询状态、单点/无点数据反馈和最新采样信息。
- 告警静默表单在提交前提供字段校验，并保留现有幂等键写入与结束操作。
- 工作区标签和结果表格增强键盘焦点、选中态、移动端横向滚动和可读性。
- 只修改监控页及其测试；不扩展为后端观测服务或其他管理页重构。

## 交互设计

### 页面级状态

- 首次进入默认加载运行概览。
- 每次切换工作区先取消该工作区上一次未完成请求，避免旧响应覆盖新查询。
- 顶部刷新按钮触发当前工作区重新加载，并显示加载态。
- 统一显示数据源不可用、请求失败和无数据三类反馈；失败信息提供再次刷新入口。

### 日志检索

- 筛选字段包括关键词、服务名、Pod、链路 ID、级别、开始时间和结束时间。
- “检索”使用当前字段从第一页开始；“重置”清空筛选并重新查询。
- “加载更多”追加结果，按钮在请求中禁用；无下一页时不显示。
- 点击结果打开完整日志详情，详情中保留时间、服务/Pod、线程/Logger、链路 ID 和原始内容。
- 输入值使用 `trim`；空值不发送给 API。

### 指标趋势

- 首次访问指标工作区时按固定目录选择第一项并查询默认 1 小时。
- 查询失败、无序列、单点序列分别有明确提示；有数据时显示最新值、时间范围、最小值和最大值。
- 服务名为空时不透传 `serviceName`。

### 告警中心

- 当前告警、规则、静默记录分别展示数量和空状态。
- 静默创建要求告警规则非空、原因至少 3 个非空字符，分钟数限制为 5–1440；不满足条件时保留弹窗并显示表单提示。
- 成功创建或结束静默后刷新告警数据；请求失败保留页面并展示错误。

## 视觉和响应式设计

- 延续截图中的深蓝到青绿色渐变头部、白色卡片、浅蓝灰边框和青绿色活动标签。
- 标签按钮提供可见 `:focus-visible` 外框；卡片标题、计数、辅助信息保持统一层级。
- 日志表格在窄屏下允许横向滚动，筛选区从多列网格降为单列；告警卡片改为单列。
- 空状态和错误状态使用稳定高度，避免页面在加载和无数据时跳动。
- 所有新增控件包含可访问的文本或 aria 属性，不依赖颜色单独表达状态。

## 测试与验收

- 在 `tests/views/system-monitor.spec.ts` 先增加失败测试，覆盖筛选重置并透传时间范围、失败后重新刷新、请求竞态取消/旧响应不覆盖、静默表单校验和空状态。
- 保留现有权限测试，确保没有对应权限时标签和懒加载接口均不出现。
- 运行：`npm test`、`npm run type-check`、`npm run build`（工作目录为 `node-base-module/base-admin-web`）。
- 验收标准：四个工作区均能进入并展示对应数据/状态；日志筛选可查询、重置、加载更多和查看详情；告警静默非法输入不会发请求；桌面与窄屏布局不出现横向溢出以外的布局破坏。
