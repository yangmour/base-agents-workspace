# G2 文件服务真实闭环设计

延续admin门面、file独立数据面与浏览器签名直传的现有架构和前端风格。按用户既定顺序补已有能力真实验收，不迁移存储到admin，也不把仅单测或旧直传脚本结果当成完整文件交付。

## 首轮证据与修复范围

当前admin制品074acb4157c68ad8及file基线8d928452254680fe。file仅在本机8085/8185运行，MinIO健康。实际匿名读取不存在租户的 `/inner/file/module?tenantId=9182000000001&actorId=9182000000301` 返回HTTP/RI200空列表，证实file入站内部HMAC校验未装配；已有契约只检查旧本地filter不存在，不能证明公共校验已启用。优先补共享Servlet校验，复用现有签名器、验证器、Redis nonce，不引入admin用户身份或认证中心依赖；保留已有base-security应用的一次验证，禁止双消费nonce。缺签名/伪签名/过期/重放失败，Redis不可用拒绝，正常admin Feign可用。

已有代码另显示真实闭环风险，须先RED再最小修复：完成上传的process_status=2被删除领取的=0条件拒绝；成功回调清空hash却按相同hash查询成功态使重试不成立；分片返回带storagePathPrefix物理key而会话存逻辑key；S3完成结果缺真实size导致超额检查落到预留量。用真实MySQL状态转换和MinIO组合验证，不只mock Mapper返回值。

页面修复保持现有组件/主题：每次模块创建使用独立幂等操作；取消/失败收尾上传预留；分片失败先终止并等待本轮全部worker，再允许重试；同文件可以重选；切换模块后展示/操作不能混用旧模块文件。生命周期/取消/响应丢失必须有针对性测试，清理失败可见，不能伪装成功。

## 真实验收矩阵

- 专用A/B普通管理员与受限账号，独立文件模块/对象前缀，凭据仅存忽略且0600的清单，令牌/签名URL/callback能力不写报告。
- 真实浏览器创建两个模块、直传小文件、分片大文件、下载核对SHA-256、删除；两轮可重复，截图遮密码，页面异常0；390px对话框/上传操作可用。
- API补非法/缺失权限、伪造tenant头、B访问A key/module/callback/分片拒绝；同回调重复与竞争不重复计数，不同实例能完成同一上传。
- 配额、声明大小与对象实际大小、取消/网络失败/重新上传、错误凭证及过期失败均验证真实状态和对象；对象与预留清理后回读确认，不使用旧脚本字面upload=200当断言。
- 整套使用专用资源并在finally注销每个已签发会话；记录非敏感资源身份、失败原样保留。真实进程未知状态不能猜测删除，必要精确清理后再退役专用夹具。
