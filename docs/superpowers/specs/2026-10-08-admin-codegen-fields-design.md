# 代码生成字段配置设计

在已验证的 CRUD 生成器上补齐字段配置，保留 base-admin-web 的选择表、生成配置和源码预览三块布局。用户已授权按 G2 顺序完善现有功能，本切片沿用此范围；不增加控件设计器、表达式、字段排序或数据库结构编辑。

## 配置与约束

每列配置为 `columnName / label / listVisible / formVisible / required`。字段顺序来自可信数据库元数据；标题最多 120 字符，不允许空白或控制字符。请求不能修改字段类型、可空性、主键、默认值或托管属性。

- 普通业务列默认保持当前列表和表单行为；可隐藏列表，且列表隐藏不改变 API 响应。
- 非空业务列展示时必填；没有数据库默认值时不可隐藏表单。有默认值的隐藏业务列由数据库填充，INSERT/UPDATE 都不能写它。
- 可空业务列可以加强为必填；该设置同时影响 Java 校验、TS 写类型和 Vue 表单，不改变数据库或响应的可空性。
- 主键、version、审计时间可配置列表显示，不能配置表单写入；主键/version 始终保留于响应供 CRUD 使用。
- tenant、审计人、逻辑删除字段固定隐藏；敏感列继续在元数据和生成器过滤，伪造未知/敏感列配置被拒绝。
- 隐藏表单字段必须从写 DTO、setter、INSERT/UPDATE 集合排除，不能因原实体的 `updateStrategy=ALWAYS` 被清空。
- 未提供 `fields`、旧库记录 JSON 为 NULL 时使用现有默认行为。显式字段配置允许部分覆盖，服务端规范化为按元数据顺序的完整配置；拒绝重复、未知或非法组合，不静默修正请求。

## 接口与持久化

`CodegenGenerateRequest` 保留原四个命名字段，新增可选 `fields` 与 `expectedVersion`，保留四参数 Java 构造器。`CodegenConfig` 在原字段后增加 `fields` 和只读恢复标记 `fieldConfigReset`，保留旧构造器；正常读取或写入结果的标记为 false。

元数据响应新增 `fieldOptions`，每项包含 `config`（默认字段配置）、`listConfigurable`、`formConfigurable`、`requiredConfigurable`、`formHideAllowed` 和中文 `restriction`。前端据此禁用非法操作，后端仍独立强校验。

增加 `PUT /admin-api/system/codegen/tables/{tableName}/config`，使用 `system:codegen:preview` 权限和已有幂等框架；请求为完整生成请求，路径与请求表名一致，保存时必须提供非负 `expectedVersion`，0 表示尚未创建。成功返回规范化 `CodegenConfig`；旧版本返回既有 `AdminConflictException` 映射的 HTTP/RI 409。

新增 V15 迁移为 `sys_codegen_config` 增加可空 `field_config_json`，以 `(tenant_id, table_name)` 原子保存配置及版本。条件更新必须防止两个 Pod 覆盖彼此：相同版本只有一个变更成功；相同内容且版本匹配可不增版本。旧客户端未带版本的预览/下载保留原自动保存语义，显式保存不接受缺版本。

预览、下载继续自动保存，但都先用同一解析器得到规范化配置，并返回实际保存的 `config`，供前端更新版本。合法标识符/字段校验发生在任何配置写入或文件发布之前；失败不改变配置。下载保存使用明确的可写事务，不在只读事务执行更新。文件发布失败与配置保存的边界保留可核对证据，不把两服务操作描述成分布式原子事务。

历史配置可能因数据库删除/重命名字段或收紧可空约束而不再合法。GET 只对非 NULL 历史 `fields` 的策略校验失败提供恢复：返回当前表的完整默认字段，保留原命名和版本，标记 `fieldConfigReset=true`。此读取不修改旧 JSON 或版本，不吞掉数据库/元数据读取故障；新提交仍严格拒绝未知字段和非法约束。用户核对后显式保存或生成，才按原版本和幂等规则更新配置。本切片采用明确告知的全字段默认恢复，不声称自动保留全部旧定制。

## 前端行为

在现有字段表中加入标题输入、列表/表单/必填勾选和限制说明，增加“保存配置”。保存失败保留输入；409 提示重新读取，不自动覆盖他人的配置。同内容保存失败重试沿用幂等键，修改内容或版本后生成新键。

`fieldConfigReset=true` 时显示“已保存字段配置不再满足当前表结构约束，已加载默认字段。请核对后保存或生成。”，字段仍可编辑。编辑不清除提示、不自动保存；保存或生成成功返回正常配置后清除提示，切表不残留。可空数值控件的空值包含 Element Plus 清空后产生的 `null`，应能提交为 SQL NULL；必填数值仍拒绝 null/undefined，任何数值输入均不能接受 NaN/Infinity。

成功预览保存请求快照与配置内容指纹（不包含 expectedVersion）。修改命名或字段后预览标记为过期且禁止下载；下载使用成功预览快照和最新确认版本。切表、卸载时取消旧请求，并通过操作编号拒绝迟到响应。预览失败可保留旧代码供查看，但必须明确其是否仍匹配当前配置。下载期间禁用配置编辑/切表，避免当前下载与屏幕状态错配。

## 验收

先建立能在旧实现上失败的字段约束/模板/页面回归。验证租户隔离、JSON 持久化、条件更新竞争、默认兼容、非法输入不写库。生成源码真实编译后确认隐藏字段更新保留原值、新增由数据库默认填充、加强必填同时被 HTTP 与 UI 拒绝、普通 nullable 仍可清空。

最终从新建独占环境实际下载 ZIP，预览/下载逐项一致；原样 Java/Vue 编译、类型及构建通过，再运行双租户/只读的两轮真实浏览器。生成器页面的保存回读、过期预览和权限使用真实浏览器验证；快速切表和迟到响应由组件回归覆盖，不将其写成浏览器已验证。记录源码及产物 hash，精确退役本轮文件、会话、夹具、桶与进程；历史失败保留。各仓库仅在相应验证和独立审查通过后提交，不推送。
