# G1 全局后台任务执行边界

保留现有管理页面、后台独立认证及任务映射的租户所有权。本切片收口已有全局 Outbox 和文件维护任务的授权及 XXL 工作线程身份清理，不把全局扫描解释为租户业务任务。

## 事实与方案

当前唯一可创建 Handler `adminTransactionOutboxDispatch` 查询全局 `mq_message_log`，该表没有 tenant_id；八个导入的文件维护 Handler 也作用于共享存储。只有按钮权限的普通租户用户目前可管理此类任务。

采用平台角色加原细粒度权限：`PLATFORM_ADMIN` 或 `LOCAL_SUPER_ADMIN` 才能读写当前全局任务目录，继续按当前可信租户限定映射。Controller 添加角色声明，应用服务和 Handler 目录再次验证，直接调用服务也不能绕过。拒绝发生在查询、事务和远端请求之前。

仅给 Controller 加注解会留下内部调用缺口；凭 executorParam 接收租户 ID 无法隔离没有租户字段的 Outbox。真正租户业务 Handler 需要领域数据和可信任务映射，另切片实现，不添加演示 Handler。

## 执行及错误边界

Outbox XXL 入口执行前及 finally 同时清理 Spring Security 和 UserContext。工作线程残留身份不恢复；XXL 的调度认证、追踪及任务上下文不受影响。成功、RuntimeException 和 Error 都须清理；保持原批次上限与失败传播。禁止从任意任务参数构造管理员身份。

原任务名、版本、幂等、归属和远端适配器保持原契约；缺平台角色返回 HTTP/RI 403，平台角色访问其他租户映射仍为 404。未注册 Handler 仍拒绝。启动阶段受控文件任务同步不依赖请求身份。

页面复用原布局和颜色；普通角色即使具有全部任务功能权限，也不加载任务数据或展示操作按钮，显示平台权限说明。平台角色仍须查看和对应按钮权限。角色/查看权限撤销时中止加载、清空任务和 Handler、关闭表单及日志。前端只是交互提示，服务端边界独立生效。

## 验收

先用参数化直接服务调用证明普通角色在所有读写及 Handler 选项上被拒绝，且 Mapper/XXL/事务无调用。证明仅 UserContext、不同用户双上下文、未认证上下文不能提权。平台两种角色正向继续通过。XXL 复用同一线程模拟残留身份，验证执行中及成功/异常/错误后均为空。

独立 HEAD 快照加本切片文件构建；完整 Maven package，原 Vue 测试/类型/构建回归。真实专用身份 HTTP 验证角色边界、伪造头拒绝、租户归属及精确注销。XXL 可用时执行真实创建/启停/立即执行/成功日志回读及重复浏览器；不可用时如实记录故障，不将其或 Kubernetes、高可用、压测列为完成。

验收报告不记录密码、令牌、原始 SQL 或全量环境。保留其他任务暂存与工作区，独立提交。

浏览器获取登录令牌后立即登记清理会话，再等待页面导航；清理失败不得吞掉。立即执行检查 HTTP/RI 200，采用远期 Cron 排除周期任务成功日志的干扰；真实成功日志需包含调度码及执行码 200。此证据只证明 XXL 手动调用链，不证明 Outbox 消息实际发送、故障重试或文件执行器线程清理。
