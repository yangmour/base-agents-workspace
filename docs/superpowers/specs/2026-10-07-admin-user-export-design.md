# G1 用户导出设计

用户已选择继续 G1 系统管理闭环。本切片在原用户管理工具栏增加“导出用户”按钮，保持现有 Element Plus 样式。独立 `system:user:export` 权限与查看权限同时满足后才显示按钮，服务端同时校验这两个权限。

采用 UTF-8 BOM CSV，而非引入 Excel 库或异步文件任务：CSV 可直接验收下载；异步任务依赖尚未完成 G2 验收的文件域。导出使用当前关键词与状态筛选，覆盖全部匹配且有权查看的数据，与页面分页无关。范围与列表共用条件构造，租户只能来自后台认证上下文，永远不接受请求租户覆盖。

后端在只读、30 秒超时的可重复读事务中按 ID 游标每批最多 500 行读取。SQL 只投影 ID、用户名、显示名称、邮箱、手机号、部门 ID 和状态；不读取凭证。生成到随机私有临时 CSV 后才发送下载响应，包含固定安全文件名、内容长度、禁止缓存和 MIME 类型。响应写入在原请求线程进行，避免异步线程丢失权限上下文。

CSV 正确转义逗号、双引号和换行，并对公式前缀及前置空白后的公式加单引号。Long 在 CSV 中保留完整十进制字符串；在电子表格导入时应把 ID 列指定为文本。上限为 100,000 行、64 MiB、每 Pod 同时 2 个导出请求。超过上限明确返回 422；并发占满返回 429。不得静默截断。完成、生成失败和连接断开都在 finally 删除本请求临时文件并释放许可；进程被强制终止后的临时目录清理由部署使用临时卷负责，归 G4 故障恢复进一步验收。

数据库连接/查询超时沿用通用 RI 500 分类；422 对应主动生成截止和行数/字节超限。生成后的事务提交失败也由事务同步回调清理文件。

导出使用 GET `/admin-api/system/users/export`，进入 EXPORT 操作审计，仅记录路径、操作者、租户、状态和耗时，不记录筛选参数、CSV 或联系方式。权限与数据范围按请求开始时确定，数据库行在同一快照中导出；请求开始后的撤权不追溯已经完成的下载，与既有列表一致。

前端使用现有认证 HTTP 客户端的二进制方法，保留令牌刷新、取消、会话切换保护和重复请求合并。JSON 错误不得作为 CSV 下载；按钮提交期间禁用，卸载时取消请求，下载后回收对象 URL。

验收：失败先行的后端及前端测试、真实 MySQL 分批与租户/范围验证、两轮真实 HTTP 与浏览器下载。浏览器解析下载文件并验证筛选、凭证排除与权限入口，截图保留原风格。此切片不宣称 G1 全部完成，也不替代 G4 容量压测。
