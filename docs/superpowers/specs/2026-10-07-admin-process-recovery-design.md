# G1 进程中断与恢复账本

已有审计 smoke 的资源身份先落盘，但 session 仅在内存。强杀发生在登录提交后、响应登记前时，保存响应令牌无法消除漏清理窗口。临时租户创建响应未登记时现有 cleanup 也跳过 id=None，列表第一页可能漏对象。

采用每轮独立平台夹具与不含秘密的持久账本：runId 决定私有凭据文件名；账本绑定 fixtureId/baseId，先落盘再准备固定身份。现有 INSERT-only 事务和精确退役校验复用。恢复只操作这轮独立身份；回收临时租户后退役其账号/角色/租户/套餐，撤销该轮所有会话，覆盖未知登录结果。普通共享夹具及历史会话不参与退役。

替代方案中，保存 Token 需要扩大秘密落盘面且仍有响应丢失空档；按照共享账号的时间窗/会话差集回收会误伤并发登录。独立身份使恢复范围明确，无需修改产品认证协议。

## 账本与并发

新增 `本地开发/tests/admin-audit-process-smoke.py`。`run --run-id <12hex>` 从零创建，`recover --run-id <12hex>` 只恢复；业务 base URL 限本机 127.0.0.1/localhost 明确端口与 /admin-api，无 userinfo/query/fragment。不支持向任意外部站点发送私有凭据。

账本放在 `target/admin-audit-process-smoke/<runId>/ledger.json`，0700目录、0600文件；拒绝符号链接、不同属主和宽权限。原子写临时文件、fsync文件、replace、fsync目录。同run文件锁使用 flock，进程死亡自动释放，活跃run与并发recover互斥。凭据固定为本地开发 `.env.admin-e2e-platform-recovery-<runId>`，0600且被Git忽略；账本校验后才访问数据库/网络。

业务状态与恢复状态独立。中断仍保留 running 或原 failed；成功cleanup不改写为passed。cleanup按追加尝试保存结果，失败后可重复。退役提交后、账本未更新时再次recover应识别已退役、验证资源不存在和会话已撤销，不尝试复活账号或重新prepare。首次prepare提交结果不明时按固定身份核实；部分/冲突及全无都拒绝报告清理成功，因为空快照不能排除仍在执行的 INSERT。保留独立身份文件，准备事务结束后可重试；本轮实际故障点均在准备完成之后，不宣称覆盖准备过程崩溃。

## 资源和故障验证

审计临时租户严格绑定 `G1AUD_<RUN>_TENANT`。无ID也按keyword精确查询；匹配>1、分页溢出、ID不一致拒绝。删除后读回为空。清理所有权校验必须发生在任何删除前。

创建请求前先持久化完整非敏感请求正文及固定幂等键。恢复用同一独立账号、相同正文和键重新发送，确认服务端创建事务结果后才查询和删除，避免客户端死亡后旧请求迟到提交造成遗漏。无法确认回放结果时不退役账号，保留可重试状态。退役事务先按升序锁住两条独立租户记录，再锁用户/会话，与生产登录的租户→用户→会话顺序一致，覆盖尚在提交的登录。

真实故障点：登录响应返回但session登记前、租户创建响应返回但ID登记前、业务完成清理前、退役SQL完成但账本确认前。受控checkpoint仅在本地验收CLI开启，外部控制器等待落盘标记后对自身创建的子进程发送SIGKILL；不杀其他进程。

验收进程恢复后核对数据库精确资源/会话0、原失败不被改写、重复recover无副作用。另用同一已验证制品启动专用第二个JVM，保留故障前Token，只杀此实例，验证存活实例可读、重启后身份及已提交状态一致。此证据限定本机共享MySQL/Redis两个JVM，不声称Kubernetes故障转移或压测完成。

现有前端不需要样式修改。中文注释、脱敏报告、复现命令和独立提交随代码交付。
