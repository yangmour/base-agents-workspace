# G1 账户启停与会话撤销闭环

> 使用 executing-plans 顺序实施；沿用已授权的 G1 独立认证和系统管理边界，每项验证后独立提交。

**Goal:** 停用后台账号时永久撤销其已有会话；重新启用后必须重新登录，并阻止停用/凭证变更期间的陈旧登录结果创建新会话。

**Architecture:** 继续使用 admin 自有账号、密码版本和共享 MySQL 会话。状态更新与会话撤销在同一事务完成；登录在密码校验后锁定目标用户行并复核启用状态及密码版本，再写入会话。bcrypt 计算在锁外执行，锁只串行化同一账号的登录提交与状态变更。

**Tech Stack:** JDK 21、Spring 事务、MySQL/JUnit、Vue/Playwright、Python HTTP 验收。

## 约束与验收标准

- 不使用 auth-center，不重置既有夹具账号密码；创建本轮唯一临时账号并精确删除。
- 停用后及重新启用后，旧 access/refresh 均为 401；新登录可成功。
- 撤销只影响当前可信租户的目标用户，同租户其他用户和其他租户不受影响。
- 版本冲突与越权请求不得修改状态或撤销任何会话。
- 并发登录与停用使用用户行的相同锁序；凭证版本已变化时拒绝旧校验结果。
- 报告不保存密码、Token、完整认证响应；异常和清理失败均返回非零状态。
