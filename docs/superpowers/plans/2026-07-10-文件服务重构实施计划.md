# 文件服务重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 保持 `FileObjectService` 和 controller 对外接口稳定，把文件服务从单个重服务类逐步拆成 application use case、domain policy、infrastructure provider 三层。

**Architecture:** `FileObjectServiceImpl` 暂时保留为 facade，每次迁移一组行为到新类。新类先补 characterization tests，再让 facade 委托新类，最后删除原实现里的重复私有逻辑。

**Tech Stack:** JDK 21、Maven、JUnit 5、Mockito、Reactor Test、Spring WebFlux、MyBatis-Plus。

## Global Constraints

- 文件路径只记录仓库内相对路径。
- 每完成一个任务提交一次。
- 生产代码变更前必须先写失败测试并确认失败。
- 不改变 `server/file/src/main/java/com/xiwen/server/file/service/FileObjectService.java` 的 public surface。
- 不移动 controller 路径，不改变 `RI<T>` 响应结构。
- 每次只拆一组职责，避免上传、回调、查询、分片和调度互相牵连。
