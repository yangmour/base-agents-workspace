# G1 后台用户密码重置

**目标：** 沿用用户表格和 Element Plus 弹窗，补齐 `system:user:reset-password` 管理入口；重置凭证和撤销全部旧会话在同一事务提交。

**方案：** `PUT /admin-api/system/users/{id}/password` 使用可信租户、按钮权限、数据范围、版本及幂等键。密码保留原文语义，要求 10–128 字符、UTF-8 至多 72 字节，凭证表只保存 bcrypt；含密码请求的幂等摘要用后台私钥保护的 HMAC，不保存可快速猜解密码的普通 SHA-256。更新递增资料版本与密码版本，保留启用状态和权限版本；复用登录提交时的密码版本复核。相同请求回放不得撤销重置后新建的会话。

**验收：** 真实两租户/双 Pod 临时账号检查旧密码、access、refresh 拒绝，新密码登录有效，越权、跨租户、无效输入、旧版本与并发请求不产生越界写入。浏览器从现有用户页重置后观察受试页面重新登录。报告不保存密码或令牌，精确清理临时数据。

## 审查后的摘要保护

- 独立审查指出普通幂等 SHA-256 暴露低成本密码校验值；真实控制器 AOP 测试复现后修复。
- 新建用户和重置密码标记敏感请求，使用共享后台私钥的 HMAC-SHA256 与固定用途前缀；每请求独立 Mac。
- 摘要采用 `h1` 标记及 248 位结果，适配现有 CHAR(64)；同密码/同键跨实例回放，修改密码仍冲突。
- V13 将旧凭证请求摘要置为不可匹配值，保留执行记录；普通资料回执和新 h1 摘要保持不变。
- 升级时先停止旧实例的凭证写入，待所有实例升级后恢复；私钥轮换后旧凭证回执返回 409，客户端应核对结果后使用新幂等键，不进行无密钥或普通 SHA 回退。
