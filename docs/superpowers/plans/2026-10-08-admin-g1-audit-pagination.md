# G1 日志与在线用户分页验收增量

**Goal:** 保留现有页面风格，用真实 HTTP 与浏览器补齐登录日志、操作日志和在线用户的跨页与筛选验证。

**Architecture:** 复用独立后台认证和专用平台双租户夹具。每轮使用全新夹具，建立精确身份的临时租户、11个A的MOBILE会话及1个B的MOBILE正对照，由各自WEB会话观察，避免在线列表的观察请求改变被测会话排序。顺序写入本轮租户11次并等待异步审计稳定；通过分页 ID 集合和真实 UI 请求/表格验证结果。

**Tech Stack:** 现有 Python HTTP 验收框架、Playwright、Vue 3、MySQL/Redis、本机 admin。

## 范围决定

用户选择优先 G1 剩余闭环。原八项已按历史分项证据收口；本增量针对明确缺少的真实分页断言，不将已完成项重置为未完成。比较三种方式：只验证API不能证明页面换页；全量重跑旧G1成本高且仍不补缺失断言；采用专用HTTP和浏览器验收器，沿用真实服务与现有样式。只有发现实际缺陷才改生产实现，另行记录失败与修复。

## 验收与边界

- 3个接口读取第1/2页：页码、页大小、total、ID不重复，合并等于同过滤稳定快照。超过有界快照上限直接失败。
- 登录日志服务端筛选本轮用户、LOGIN、成功，再逐行验证11个MOBILE事件；当前接口没有设备筛选，不增加虚构参数。在线服务端筛选MOBILE。操作日志服务端筛选本轮操作者、UPDATE、SYSTEM_TENANTS，返回每行均须是本轮精确请求路径；当前接口没有requestPath筛选，不能只在客户端过滤后假称API通过。
- B同名账号建立自己的MOBILE会话，针对A本轮精确临时租户发带正确版本的PUT，验证403且A字段/版本不变，再成功读取自己这条拒绝审计；B日志及在线ID与A不相交，不以空结果代替正对照。
- 浏览器三页面真实选择10条/页、进入第二页、更改筛选和页大小后回第一页；请求参数、返回ID与表格一致，页面异常0。
- 新建全新双租户夹具，不复活历史已退役身份。令牌仅内存，不写报告/截图/trace；异常固定分类。
- 每轮finally仅注销自身会话并验证access/refresh失效、精确删除临时租户，保留审计记录。进程中断后由夹具退役覆盖未知会话，不能把旧cleanup入口描述为自动恢复内存令牌。
- 两轮独立运行并保存脱敏证据；本地单admin的分页证据不代表跨Pod、实时推送或容量SLA。
