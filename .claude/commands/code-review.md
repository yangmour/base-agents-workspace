# 代码运行安全审计

对用户指定的文件、目录或当前 Git 变更进行安全优先的代码审计。目标是发现代码在运行时可能被攻击者利用的问题，降低注入、越权、数据泄露、文件攻击、配置错误和依赖漏洞风险。

## 使用范围

适用：

- 审核后端服务代码（Java、Python、Go、Node.js 等主流语言和框架）。
- 审核前端代码（Vue、React、Angular 等主流框架及原生 JS/TS）。
- 审核接口契约、请求封装、鉴权逻辑、多租户与多业务隔离。
- 审核数据库访问、文件上传下载、缓存、消息队列、外部调用、配置和依赖。
- 审核当前 Git 变更中的安全风险。

不适用：

- 不做攻击执行、扫描外部目标、绕过检测或破坏性验证。
- 不生成可直接用于真实攻击的利用脚本。
- 不把普通代码风格问题放在安全问题之前。

## 审计流程

1. **确认审计范围**：优先使用用户给出的路径；未给路径时审计当前 Git 变更文件。
2. **读取相关上下文**：目标文件、相邻调用方、被调用方、配置、类型定义、请求封装和权限相关代码。
3. **建立运行链路**：明确入口、用户可控输入、权限上下文、数据流、外部系统调用和输出位置。
4. **按攻击面检查**：优先查找能造成未授权访问、数据泄露、远程代码执行、任意文件读写、注入和业务隔离失效的问题。
5. **区分风险等级**：只把可实际触发且影响明确的问题列为高等级；不确定项标为"需确认"。
6. **给出修复建议**：说明应改的位置和防护方式，示例代码只用于防御修复，不提供可武器化利用代码。

## 核心检查项

### 1. 输入、注入与执行安全

- **SQL 注入**：是否拼接 SQL 字符串、使用不安全的动态查询条件（如 `${}` 插值、动态表名、动态排序字段）。
- **命令注入**：是否把用户输入传给系统命令执行接口（如 `exec`、`spawn`、`subprocess`、Shell 参数）。
- **表达式注入**：是否执行用户可控的表达式、模板、动态脚本（如 SpEL、OGNL、JINJA、EL 等）。
- **NoSQL / 缓存注入**：是否将用户输入直接作为 key、pattern、查询结构或脚本参数（如 Redis、MongoDB、Elasticsearch）。
- **反序列化风险**：是否反序列化不可信数据，多态类型、默认类型开关是否安全。
- **XML 外部实体（XXE）**：XML 解析是否禁用外部实体（DTD / ENTITY）加载。
- **模板注入（SSTI）**：服务端模板是否渲染用户可控内容。

### 2. 认证、授权与隔离

- Token / Session 校验是否完整，过期、刷新、吊销、签名和异常分支是否正确处理。
- 后端接口是否缺少权限校验，是否只依赖前端菜单、路由或按钮控制。
- 是否存在水平越权（IDOR）、垂直越权、批量操作越权。
- 多租户、多业务线、多应用等隔离维度是否在服务端强制校验，不信任客户端传入的归属标识。
- 管理接口、内部接口、服务间调用接口是否有独立的访问边界和可信调用约束。
- 密码重置、邮箱/手机验证等流程是否存在可预测 token、无效期限制或可枚举漏洞。

### 3. 敏感数据与日志

- 密码、令牌、密钥、验证码、身份证号、完整手机号、邮箱、地址等是否进入日志或异常堆栈。
- API 响应是否暴露密码散列、内部 ID、权限全集、异常堆栈、系统路径或配置信息。
- 前端本地存储（`localStorage`、`sessionStorage`、IndexedDB、Cookie）是否保存高敏感数据。
- 配置文件、测试数据、脚本、版本历史中是否包含硬编码密钥、默认账号或数据库连接串。
- 错误处理是否泄露数据库类型、框架版本、服务器信息或内部路径细节。

### 4. Web 与前端安全

- 是否使用框架提供的 HTML 原始渲染指令（如 `v-html`、`dangerouslySetInnerHTML`）渲染未净化内容，引发 XSS。
- 用户输入是否进入 HTML、URL、样式、脚本上下文而未做转义或净化。
- CORS 是否过宽，是否允许任意来源携带凭证（`Access-Control-Allow-Origin: *` + `credentials: true`）。
- Cookie 属性（`HttpOnly`、`Secure`、`SameSite`）、Token 存储和过期处理是否安全。
- 前端权限控制是否被误当作最终授权，服务端是否有对应强制校验。
- 请求封装是否统一处理 401、403、业务异常和令牌刷新失败，避免敏感错误信息透传。
- CSP、`X-Frame-Options`、`X-Content-Type-Options` 等安全响应头是否配置。

### 5. 文件、路径与外部请求

- 文件上传是否限制大小、扩展名、MIME 类型、文件真实内容（魔数校验）和存储路径。
- 文件下载是否存在路径穿越（`../`）、任意文件读取、对象越权访问。
- 解压缩是否存在 Zip Slip（路径穿越）、压缩炸弹或超大文件风险。
- 图片、文档、办公格式、PDF 等解析是否限制格式、大小和解析器安全行为。
- **SSRF**：后端是否请求用户可控的 URL、Webhook、图片地址、回调地址，是否限制内网 IP 段和云元数据地址。
- 重定向是否允许用户控制目标地址（开放重定向），是否有白名单约束。

### 6. 数据库、缓存与并发安全

- 数据库查询是否强制附加必要的隔离条件（如租户、逻辑删除、数据权限范围）。
- 批量更新、批量删除是否有完整过滤条件，防止误操作全表。
- 分页和排序字段是否经过白名单校验，防止注入和信息探测。
- 缓存 key 是否可被用户枚举或污染；不同用户/租户/会话的缓存是否有效隔离。
- 分布式锁 key 是否可被外部控制，锁的获取与释放是否原子安全。
- 并发场景是否存在 TOCTOU（先检查后使用）、重复提交、库存/余额类竞态风险。

### 7. 配置、依赖与运行环境

- 安全框架（如 Spring Security、Passport、Django Auth 等）的白名单、CORS、调试接口是否在生产环境过宽暴露。
- API 文档接口（Swagger、OpenAPI、Knife4j 等）和监控管理端点（Actuator、metrics 等）是否在生产限制访问。
- 中间件（数据库、缓存、消息队列、配置中心等）是否使用默认口令或过宽权限。
- 第三方依赖（Maven、npm、pip、go mod 等）是否过旧或存在已知高危漏洞迹象。
- 构建脚本、CI/CD 配置是否泄露密钥，或跳过安全扫描步骤。
- 容器镜像、运行用户是否遵循最小权限原则。

## 项目上下文适配

在开始审计前，请先了解目标项目的以下信息，以便针对性地调整检查重点：

- **技术栈**：使用的语言、框架、ORM、缓存、消息队列等。
- **认证机制**：JWT / Session / OAuth2 / API Key 等，以及 Token 的签发、刷新和吊销方式。
- **隔离维度**：是否有多租户、多业务线、多应用、多客户端等隔离需求及其实现方式。
- **统一规范**：项目是否有统一的响应结构、错误码、异常处理、日志规范和权限模型。
- **服务边界**：内部服务间调用的信任级别和鉴权方式（如 Feign、gRPC、HTTP 内网调用等）。

如用户未提供上述信息，审计时遇到相关代码应主动标注"需结合项目规范确认"。

## 风险等级

### 严重

满足任一条件：可导致未授权访问、权限绕过、敏感数据泄露、任意文件读写、远程代码执行、命令执行、SQL 注入、SSRF 访问内网、跨租户或跨业务线数据访问。

### 高

满足任一条件：认证或授权边界不完整、批量越权、敏感数据进入日志、文件校验不足、生产配置过宽暴露、安全控制可被稳定绕过。

### 中

满足任一条件：输入校验不足但利用条件受限、错误信息过多、依赖或配置存在潜在风险、异常处理可能导致安全行为不一致。

### 低

满足任一条件：安全可维护性不足、防御纵深不足、日志审计不完整、命名或结构影响后续安全治理。

## 输出格式

按以下结构输出：

```markdown
## 审计范围
- 路径：...
- 审计对象：后端 / 前端 / 配置 / 依赖 / 当前变更
- 技术栈：...（如可识别）
- 关键入口：...

## 总体结论
- 风险等级：严重 / 高 / 中 / 低 / 未发现明显风险
- 主要风险：...
- 优先修复：...

## 发现的问题

### 1. [严重|高|中|低] 问题标题
- 位置：`file_path:line_number`
- 攻击面：用户输入 / 接口参数 / 文件 / 配置 / 外部回调 / 依赖
- 风险说明：...
- 触发条件：...
- 影响范围：...
- 修复建议：...
- 防护示例：...

## 检查通过项
- ...

## 需确认项
- ...（需结合项目规范或运行时上下文确认）

## 修复优先级
1. ...
2. ...
3. ...
```

## 审计要求

- 问题必须给出具体位置，格式使用 `file_path:line_number`。
- 不确定的问题不要夸大，放入"需确认项"。
- 修复建议优先给最小安全改动，不引入无关重构。
- 如果未发现明显风险，也要说明已检查的攻击面。
- 不输出可直接攻击真实系统的利用脚本、批量扫描脚本或绕过检测方法。

## 使用方法

```text
/code-review path/to/file.java
/code-review path/to/directory
/code-review
```

未传路径时，默认审计当前 Git 变更。
