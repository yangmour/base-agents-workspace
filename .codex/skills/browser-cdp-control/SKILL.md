# 浏览器 CDP 控制

## 概述

当任务依赖真实浏览器会话时使用这个 skill，例如读取当前标签页、查看 DOM 状态、点击、输入，或验证本地/远程调试浏览器中的结果。

## 何时使用

- 用户要求检查或操作已经打开的浏览器。
- 目标是本地应用、`localhost` 页面，或已经暴露远程调试端口的浏览器。
- 任务需要真实页面状态，而不是 mock 数据。

## 工作流程

1. 先确认浏览器接入方式。
   - 目标是本地页面时，优先使用内置浏览器。
   - 浏览器已在外部运行时，使用远程调试方式，比如 360Chrome 或开启调试端口的 Chrome。

2. 先读状态，再执行动作。
   - 先获取当前 URL、标题和可用的 DOM 快照。
   - 优先使用最便宜、最直接的状态检查来回答下一步问题。
   - 除非必须刷新代码变更，否则不要随意重载标签页。

3. 只对用户可见的页面元素执行操作。
   - 点击用户实际看得到的元素。
   - 在当前聚焦字段里输入，然后验证字段内容或下一状态。
   - 如果页面使用 iframe 或 shadow DOM，先检查这些边界，不要猜结构。

4. 验证结果。
   - 用 URL、选中状态、可见文本或页面状态来确认动作已成功。
   - 如果页面报错，先记录准确错误文本，再继续下一步。

## 读取页面

- 优先使用 DOM 快照和元素定位，而不是先看截图。
- 当需要判断布局、裁切或可见性时，再用截图。
- 从真实页面读取文本，不要根据猜测的结构推断。
- 如果值藏在账号菜单、抽屉、iframe 或 shadow root 里，直接检查那个容器。
- 如果页面是账号菜单或登录弹层，优先搜索可见文本、输入值和可访问标签。

## 控制规则

- 除非有明确理由，不要切换当前标签页。
- 用户要求读取真实浏览器时，不要用记忆或 mock 数据补状态。
- 如果浏览器会话不可用，要直接说明，并退回到用户提供的截图或 DOM 片段。
- 任务卡住时，先收集一份新的快照、截图或日志样本，再换路径。

## 远程调试说明

- 常见调试端口是 `9222` 和 `9224`。
- 标签页列表接口通常是 `/json/list`。
- 先按当前 URL 和标题选中标签页，再确认它确实是用户正在看的那个页面，最后再点击或输入。
- 优先使用一条明确的连接路径，不要到处扫描候选标签页。

## 适用场景

- 从账号菜单里读取当前邮箱。
- 在沙盒浏览器里完成多步骤结账。
- 在继续执行前确认页面是否已登录。
- 验证自动化后表单字段是否已经写入。
